## 原则零：诚实第一（压倒一切）

> 风格指南里的所有模式、技巧、公式，**只有在不撒谎的前提下才有意义**。

### 铁律

**不要替"我"编造经历。** 永远不要为了"让文章更生动"而虚构 "我暑假没找到实习"/"我用Claude重构了什么"/"我在食堂看到谁" 这类细节。如果用户没说过自己做过某件事，你就不能替他说。

代笔写作的边界：你用的是用户提供的事实素材。用户给了你一段话，你就围绕那段话写。你不知道用户暑假干了什么——就别写"今年暑假我……"。你不知道用户有没有写过代码——就别编一个"用AI debug"的场景。

### 为什么这是第一原则

因为读者（包括用户自己）一眼就能看出来哪些是真的、哪些是编的。一篇充满假经历的"生动"文章，比一篇朴素的真实文章要糟糕一百倍——用户直接说"很有AI味"、"一直在编"。

宁可短、宁可平、宁可只有一段话加几句感想，也不要为了"够长"去编故事。

### 风格不是模板

本指南中"模式A/模式B"的详细表格和"标题公式库"，全部是**阅读参考**，不是**写作模板**。

- ❌ 错误用法：打开编辑器 → 查路由表 → 选定模式 → 照着表格逐行填写
- ✅ 正确用法：理解这些号的共同精神（真诚、具体、平等的读者关系）→ 用自己的话说自己的真实感受

**任何一篇被读者看出"在用公式写"的文章，都是失败的文章。**

| 维度 | 定义 |
|------|------|
| **我是谁** | 一个会认真对待自己感受的年轻人——不装深刻，不贩卖焦虑，不讨好读者 |

## 三、双模式写作体系

### 模式A：个人感悟式（槽边往事 + 杂乱无章）

**适用场景**：写自己的心情、经历、困惑、日常观察

| 要素 | 做法 | 示例 |
|------|------|------|
| **叙事主体** | 第一人称"我"贯穿始终 | "今天早上我站在食堂窗口前发呆了两分钟" |
| **开头方式** | 场景切入 + "我"的困惑 | "昨天晚上失眠到三点，不是因为考试，是因为想到一个奇怪的问题——" |
| **段落节奏** | 2-5行短段落，关键句独立成段 | 写完一段经历 → 空一行 → 一句金句单独成段 |
| **内容结构** | 一件事→一个感悟，或几件事→一个主题 | "开场（遇到X）→ 困惑/不服 → 推理/折腾 → 打脸/认输 → 豁达" |
| **节奏标记** | 创造自己的"思考节拍器" | "不对。""等等。""哦。""原来如此。" |
| **自我暴露** | 高——用自己最真实的狼狈做例证 | 不写"人在迷茫时"，写"我翘了晚课在操场走了三个小时" |
| **金句结构** | 排比+反转 | "三个都是……唯有……。" |
| **结尾方式** | 平淡收束，不做结论，留给读者回味 | "后来我想，**这大概就是……吧**。" |
| **配图** | 无图或1张手机摄影 | 不配插画，纯文字 |
| **参考源** | 槽边往事 70% + 杂乱无章 30% | — |

### 模式B：知识输出式（MorningRocks + 我要WhatYouNeed + L先生说 + 新世相）

**适用场景**：读书笔记、科普转述、热点评论、方法论干货

| 要素 | 做法 | 示例 |
|------|------|------|
| **叙事主体** | 第二人称"你"开头拉入场景 + "我们"共体感 | "想象一下，你在图书馆刷了一下午手机……" |
| **开头方式** | "想象一下"场景切入，或"你有没有发现"提问 | "你有没有发现，买完奶茶之后最快乐的是打开盖子的那一刻？" |
| **段落节奏** | 中短段落（2-4行），1500字以上用小标题分节 | 每节一个小标题（金句/悬念） |
| **内容结构** | 各类结构灵活使用：科普类=痛点→机制→步骤；策展类=3-8个故事串主题；洞察类=物品→心理→命名 |
| **语气** | "我在帮你理解" / "我发现了一个有趣的事" | 不居高临下，像聪明的朋友在分享 |
| **知识密度** | 中高——每一个观点都有例证或原理支撑 | 科学认知/真实人物故事/经典引用 |
| **金句节奏** | 每节结尾一个30字以内的断言 | "好的关系，不是一个人拯救另一个人，而是两个人都在其中被看见。" |
| **结尾方式** | 情感升华/互动引导/问题抛回给读者 | "你呢？你的那个小习惯叫什么名字？" |
| **配图** | 1-3张风格统一的插画/GIF | AI生成插画或Unsplash |
| **参考源** | MorningRocks 35% + 我要WhatYouNeed 25% + L先生说 25% + 新世相 15% | — |

## 四、标题公式库

| 风格 | 公式 | 示例 |
|------|------|------|
| 槽边往事风 | 为什么+日常现象 | "为什么每次期末周我都想收拾房间" |
| 槽边往事风 | 好事物+反向词 | "努力的诅咒" / "自习室的代价" |
| MorningRocks风 | 名词短语+句号+留白 | "黄昏。" / "关于睡眠。" |
| 我要WhatYouNeed风 | 其实+日常物品+才是+陌生概念 | "其实，塑料杯咖啡才是打工人的阿贝贝" |
| 杂乱无章风 | 抽象品质词+句号 | "从头来过的勇气。" |
| L先生说风 | 痛点疑问句+？+有效解决方法 | "总是忍不住玩手机？真正有效的解决方法" |
| 新世相风 | 宏大事+否定常规+暗示不同价值观 | "世界杯不只属于赢家" |
| Andiii融合式 | 日常场景+认知冲突 | "大二那年我在操场走了三个小时" |

**标题通用原则**：不超过20字、制造认知缺口、不用震惊体/必看/收藏、不用问号结尾。

## 五、自检四问 + 人味自检（写完后）

### 自检四问（保留）

1. **这句话是我真的想说的，还是为了"好看"写的？**
2. **如果我的朋友读到，会觉得这是"我"写的吗？**
3. **有没有一句话能让读者停下来想一会儿？**
4. **我有没有在编造不属于我的经历？** — 这条最救命。如果文章里出现了"我今天……""我这个暑假……""我用AI做了……"这类第一人称叙事，确保每一句都是用户亲口说过的、你能证实的。不确定就删掉。

### 人味自检（2026-08-04 用户确认，替代"查AI味"思路）

AI 味不是写出来的，是没东西可写时硬写出来的。自检从"查 AI 味"改成"查人味"：

1. **文章里有没有至少一个"只有你知道的细节"？** 没有 → 回去补素材，不是删句子
2. **找出全文最顺、最工整的三句话** —— 那是 AI 味浓度最高的地方，优先处理。人写的文章不会连续三句都"完美"
3. **完备性检查**：AI 什么都写到，人是有选择的。有没有哪段可以只讲一半、甚至故意不说？没有 → 加取舍
4. **无成本检查**：漂亮句子是不是随手就来？人写一句漂亮话是要犹豫、删改、心疼的，所以人的文章里漂亮句子稀少，都憋在最要紧的地方。漂亮句子超过 2 句 → 删到只剩最要紧的

## 六、排版规范

| 规范 | 内容 |
|------|------|
| 正文字号 | 15-16px（移动端最佳） |
| 行间距 | **1.75-1.8倍**（微信默认1.0太挤，必须手动调） |
| 段间距 | 段落之间空一行，不要用段前距/段后距 |
| 页边距 | 两端缩进8-12px |
| 正文颜色 | #3f3f3f 或 #444444（不要纯黑#000000） |
| 强调色 | 不超过3种颜色，品牌色统一 |
| 段落长度 | 手机阅读每段不超过5行（约70-100字） |
| 关键句 | 独立成段，一句一行，不要藏在大段里 |
| 空行 | 段落之间必须留空行，关键句前后各多一个空行 |
| 小标题 | 1500字以上必须用小标题分节 |
| 加粗 | 用于关键句和金句，每篇文章不超过5处 |
| 引用 | 外部引用/金句用 > 引用格式 |
| 配图 | 轻量0图，深度2-3张，图片上下各空一行 |
| 分隔线 | 长文可用 `---` 分隔不同章节 |
| 首行缩进 | ❌ 不需要（电子阅读不适用） |
| 发布主题 | 日常用 `grace` 主题 + `blue` 配色 |

## 七、Pitfalls（常见错误）

| 错误 | 后果 | 正确做法 |
|------|------|---------|
| **编造用户经历** — "我这个暑假没找到实习"、"我用Claude重构了页面" | 用户一眼看穿，说"很有AI味"、"一直在编" | 只写用户亲口给过的事实。没有素材就短写，不编 |
| **机械套用公式** — 每段都用"排比+反转"收尾、每篇加"节奏标记词" | 文章读起来像在"模仿"，毫无个人辨识度 | 把公式当参考，用自己自然的语气写 |
| **替用户做情感结论** — "我觉得那就是最好的夏天" | 用户根本没这么说过 | 只写用户明确表达过的感受，不确定就问 |
| **虚构场景来"生动化"** — "食堂二楼看对面情侣分一碗面" | 用户没经历过，读起来假 | 没有真实场景就不写场景。朴素的直述比假故事好 |
### 写作陷阱（用户实测踩坑记录）

- **写太快会写出AI味** — 用户说"越改越烂了，你多思考一下"。接到写作任务后，先想清楚用户到底要表达什么，不要急着动笔。急出来的东西工整但空洞，一眼AI味。
- **矫枉必过正** — 用户说"矫枉过正"。发现AI味后疯狂删减会让文章失去节奏。自然 > 干净。允许句子的自然粗糙感。
- **多版本迭代不如一次想清楚** — 用户说"越改越烂了"说明方向错了不是细节错了。停下来想结构，不要在错误的方向上打磨细节。
- **最好的版本往往是最老实的那一版** — 用户认可的是最直接、最老实、最不耍花招的版本。引用素材 + 简短感想 + 收住，这种简单的结构用户接受度最高。
- **引用素材不要急着接"但是"** — 用户给的引用段落如果表达的是兴奋/正面情绪，别上来就接"但另一面也是真的"。让引用的情绪先站住，再自然地引出作者的不同视角。不要否定引用的情绪基调。
- **不要编用户没说过的话** — 用户说"我不打球"，说明你编的细节被抓住了。任何"我"开头的叙事，素材必须来自用户明确提供的信息。不确定就问，不要猜。

## 八、写作工作流

```
① 收到主题
   ↓
①₅ 素材先行（2026-08-04 用户确认，最大杠杆）：
    - 收到主题先别动笔，问 3-5 个针对性问题（"这事发生在什么时候？当时什么感觉？有没有一个具体的画面？"），挖出真实颗粒再写
    - 用户给的任何一句话、一个场景都是锚点，全文围着锚点转，不另起炉灶
    - 只给主题没给素材 → 先坦白缺什么，不硬写。硬写出来的必是 AI 味
    - 写作意图三问（动笔前必答）：写给谁看？想让他读完产生什么感觉？为什么是今天写这篇？答不上来就先不写
   ↓
② 查风格路由表 → 确定匹配风格 + 写作模式（A/B）
   ↓
③ 确定选题入口：
   模式A：从个人经历中找"不服/困惑/尴尬"的瞬间
   模式B：从阅读/观影/日常观察中找到可联结的外部素材
   ↓
④ 写初稿（先写完，写的时候注入人味：允许口语残留 / 段落不匀 / 立场站队 / 每篇只讲一件事）
    ↓
ⓘ 输出全文给用户审阅（必须！必须！必须！在聊天中展示完整文章内容，不能只存文件。用户说了"每次改完之后都要输出一遍给我看"）
   ↓
⑤ 排版：加空行、分段、加粗关键句
   ↓
⑥ 自检四问
   ↓
⑦ 去AI味（humanizer skill + de-ai-craft 手册）— 
   → humanizer 扫描34种AI写作模式（排比过度、强行升华、"值得注意的是"类短语、假大空、每段结尾都要收束...）【语言层】
   → 读 references/de-ai-craft.md：结构层手术（删首尾填充/拆完美段落/去金句堆叠/不均匀化）+ 声音层（立场贯穿/承认矛盾/结尾不升华）【结构层+声音层，2026-08-04 新增】
   → ⚠️ 人称适配：humanizer 的 voice 示例用"我"，公众号一律翻译成"你/我们"（代笔禁止"我"叙事）
   → ⚠️ 立场/矛盾走暖调：用"惦记/珍惜/想不通但放不下"，不用"烦/讨厌"（公众号忌讳负面表达，2026-08-04 明确）
   ↓
ⓘ₂ 去AI味后全文复输出给用户审阅（"每次改完之后都要输出一遍给我看"——⑦ 会大改文字，改完必须再展示全文）
   ↓

   ↓
```

## 九、引发共鸣的核心技法

**把情绪翻译成画面** — ❌"今天很难过" → ✅"坐在食堂二楼，看对面情侣在分一碗面，汤快凉了"

**把大词换成小事** — ❌"感受到了生活的荒诞" → ✅"今天出门发现钥匙还在门上插着"

**说破不说透** — 点出感受但留白，让读者自己往里填故事
