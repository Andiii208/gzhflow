# 阶段⓪ Run 模式（一次任务怎么自动跑完）

> 2026-10-12 建（v5B §3）。**这个文件管"一次任务"，SKILL.md 的七阶段管"每个环节怎么做"。**
> 全文的起点是一句判断：**全自动的核心不是堆自动化，是三件事——**
> **把人工把关换成确定性校验、把生图决策换成 manifest+预算前置、把无限打磨换成轮次封顶。**

## 一、一次 Run 的定义

```
输入（三选一）    全自动 Run（墙钟 ≤40 分钟，目标 25）                         输出
──────────────    ─────────────────────────────────────────────────────────    ─────────────────────
· 一句话选题      ① 收件箱/选题 → ② 读范文锚写作 → ③ 手术+冷读                 成品文件夹：
· 收件箱素材      （各 1 轮，自动修复 ≤1 轮封顶）                              · 预览页（一键复制）
· 一篇草稿        ④ 图源三问 → 实体色板 → manifest → 并行生图（正文 ≤4 张）    · 带图副本 + 干净正文
                  ⑤ 主题自动选 → 装配 → 校验器 ERROR=0                         · 体检报告
                  ⑥ 预览页 + 报告 + 决策日志                                   · 决策日志
                                                                               · 预算消耗单
```

**四条硬约束**：

1. **墙钟 ≤ 40 分钟**（目标 25）
2. **正文配图 ≤ 4 张**（1 封面 + 2–3 内文）。**金句卡/封面变体等附加产出按需追加**——
   预算管的是「乱生图」（manifest 之外不生成），**不是限制内容品类**
3. **成本上限可配**（默认 ~$0.3/篇）
4. **人的介入点 = 2**：开头给信息一次，结尾看预览拍板一次。**中间零提问**

> **发布永不进 Run。** 推草稿箱是显式授权的独立动作（安全边界，不自动化）。

## 二、双模式

| 模式 | 行为 | 怎么触发 |
|---|---|---|
| **全自动**（默认） | 零提问跑完。所有本该问人的决策落**决策日志** | 直接给信息即可 |
| **交互** | 在选题/框架处暂停等确认，保留 v5 的人工节拍 | 用户说「交互模式」 |

全自动模式**零配置可跑**：一切有默认值（正文图 4 张、内文 medium / 封面 high、$0.3 上限），
都可按需上调。配置在 `config/workflow.yaml` 的 `image_budget`。

## 三、Run 状态机（断点续跑）

`state.md` 的「当前篇」要记到 **step 级**，每阶段完成即落盘：

```
状态: run
run step: ④ 配图 (in_progress)
已完成: ①素材 ②写作 ③去味
```

**规则**：
- 每完成一个阶段，立刻把 `run step` 推进并记下已完成的阶段清单
- 断线/失败后**从断点恢复，不重跑已完成的阶段**——这是 40 分钟硬约束的保底：
  最好的情况跑得快，最坏的情况能续
- 阶段内失败按各阶段自己的降级规则处理（如配图失败留 `.FAILED.txt` 继续走完）

## 四、决策日志（不问，但全部交代）

全自动模式不提问，所以**必须把决策交代清楚**，写到 `generated/决策日志.md`：

| 记什么 | 例子 |
|---|---|
| 选题来源与理由 | 「用了收件箱第 3 条，因为它是唯一有具体场景的」 |
| 主题选择与理由 | 「选纽约客编辑风，因为这篇是思辨向」 |
| 文章类型判定 | 「判定为说理（genre: 说理），因为它有明确论点」 |
| 图片清单/图源分轨与预算 | 「1 封面 high + 2 内文 medium；事件本体 2 块走真实图轨（官方 logo + 同人图），概念位 1 块走 AI；预估 $0.27，上限 $0.3」 |
| 自动修复了什么 | 「③ 机器门报 2 处起首语，已改；未动其他」 |
| 降级与未完成 | 「inline-2 生图失败 2 次，留了 .FAILED.txt」 |

**这是交付的一部分，不是可选项。** 用户不看这个，就没法在下一次给系统纠偏。

## 五、轮次封顶（时长控制的另一半）

一个多小时的任务，一半是生图慢，另一半是**模型自我循环**。从机制上掐掉：

- 每个 LLM 环节（③a 手术 / ③b 冷读 / ③c 评审）**最多 1 轮自动修复**
- 修完仍不达标 → **带报告交付**，不再打磨，把问题写进决策日志
- 不做「再试一次可能更好」的循环。质量靠 ③ 的设计，不靠反复重写

配图侧同理：单张图重生 ≤2 次（见 `quote-card.md` / `04-images.md`），仍失败就降级。

## 六、Run 里的确定性与降级

| 环节 | 人工把关原来靠什么 | 现在换成 |
|---|---|---|
| 排版 | 人眼校对 | `validate_gzh_html.py` ERROR=0 + 交叉核对 `##`/`>`/`![]` 是否全在 HTML 里 |
| 配图 | 人挑图 | manifest + 预算门 + 质检门（PASS → 过预算 → 生成） |
| 去 AI 味 | 人读一遍 | `ai_flavor_score.py` FAIL 清零 + 轮次封顶 |
| 发布 | —— | **不自动化**，显式授权才推 |

人只做两件机器做不了的事：**开头给信息**（决定写什么）、**结尾看预览**（决定发不发）。
