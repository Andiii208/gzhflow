# 歌单总结类文章工作流（网易云歌单链接 → 公众号推文）

> 2026-08-05 实测：用户发来「分享歌单」链接（1301 首），要求写推文。连否 3 版（①核心围绕陶喆 ②数据罗列+空泛感慨 ③乐评式逐首拆解）后，用户点名要学「歌单总结」的写法。适用：用户丢一个网易云歌单链接让写文章的任意场景。

## 0. 触发与写法区分（用户明确）

| 用户给什么 | 用什么写法 |
|---|---|
| 点名某歌手/某几首歌（top3、最爱、深夜循环） | **乐评式**：逐首分析编曲/歌词/专辑背景（见 music-article-workflow.md） |
| 丢整个歌单链接、说「读一读，写一篇」 | **歌单总结式**（本文件） |

**歌单总结式 = 网易云年度听歌报告的写法**：
- 结构：总数 → 最爱歌手榜 → 曲风线 → 年份时间线 → 几首单独记 → 收束
- 每块 = 数据 + 一句有温度的话，短段落
- 🔴 **不逐首点评、不分析编曲**（那是乐评，用户明确否：「我要你学习学习歌单总结的风格写法啊！」）
- 🔴 数据罗列 + 空泛感慨 = AI 味（用户否 v2：「ai味很足，你这个也不全面」）
- 🔴🔴 **感染力 = 网易云官方年报文案调性（2026-08-05 最终拍板）**：v4/v5「数据+温暖一句话」结构仍被否，用户原话「你这写的感觉没有网易云官方的那种年度报告更有感染力」。达标手法（v6 方向对了、火候还不够，下次直接拉满）：
  - **数据都是「你的」**：你的年度歌手、你的听歌关键词——第二人称数据对话感（年报核心）
  - **每段一个数据 + 一句点睛**（官方句式：「总有一首歌，是为了此刻」「原来，音乐就是生活的注脚」）
  - **「你爱的 TA，变成了星星。」**：2025 官方年报原句，就是为离世歌手（方大同）写的；歌单里有逝者大量曲目时直接用这句式是真实戳心，不是硬抄
  - **听歌关键词收束**：从数据里提炼一个词（本案例「反复」：反复听同一条线/反复回到老歌）
  - **结尾年报式收束**：「音乐还在，喜欢就还在。」（官方同款：「世界晚安，音乐还在」）

## 1. 歌单全量拉取 + 口味分析

API 细节见 `netease-playlist-data.md`（trackIds 全量 → `/api/v3/song/detail` 每批 100 首；⚠️ 500/批返回 0）。本文件只补写作侧用法。

## 2. 数据分析角度（写前必跑）

- 歌手 Counter：`tracks[].ar[].name` → 统治级歌手 + 梯队（本案例：陶喆 87、方大同 45、孙燕姿 21、TS 20…）
- 年份分布：`publishTime/1000 → year` → 听歌最凶的年代、放缓年份（2016–2019 高峰、2023 全年仅 22 首）
- 最近加入的歌 = trackIds 顺序尾部（⚠️ 注意排序 ≠ 用户说的「第一首」，见下）

## 3. 素材纪律（2026-08-05 实测，用户原话级）

- 🔴 **「第一首」必须问清指代**：API 里 My Anata 排第一，我写成「歌单第一首」，用户暴怒：「陶喆的第一首是anata，谁他妈跟你说所有的第一首是啊」——那是**陶喆的第一首**（听他的起点），不是歌单第一首。不确定就写「从 My Anata 开始——那是听他的第一首」这类安全表述，或直接问。
- 🔴 **不要核心围绕单一歌手**：陶喆 87 首占 6.7% 很显眼，但用户明确「我不要核心围绕陶喆」。统治级歌手只占「最爱歌手榜」一行，不当文章主线。
- ⚠️ **「喜欢的音乐」是网易云默认歌单名**：用户没起名，**开头不要强调「名字是默认的」**（用户爆粗：「你他妈在开头强调歌单的名字是默认的干啥？」）——直接进数据，名字一句带过或不提。默认名≠文章素材。
- ⚠️ **歌单总结要「全面」，不能只列歌手**（用户：「你只说歌手有哪些歌，是不是太片面了？」）：必须覆盖 曲风线 / 语种分布 / 年份时间线 / 最老最新歌曲 / Live 版特征 / 遗作专辑 / 2-3 首具体歌曲（专辑+年份+核实过的歌词或热评）。歌手榜只是其中一块。
- ⚠️ 用户说某素材「这不重要」→ 别当重点展开（本次用户说补听「不过这不重要」）。
- 引用热评走 netease-hot-comments.md 的老版 API；引用歌词原句必须核实一字不差（music-article-workflow.md §1）。
- 可用情感支点：歌单大头歌手若有重大事件（方大同 2025-02-21 去世，45 首在歌单）→ 热评区最高赞常是悼念，是天然共鸣点（「方大同这个不喜欢前奏的男人，连离开都没有前奏」）。

## 4. 结构模板（2026-08-05 年报调性版；用户要求「像网易云官方年报一样有感染力」）

```
标题：数字式（《八年，1301 首》）
开头：直接进总数（「八年，1301 首。」+ 一句年报式开场，不解释默认名）
① 你的年度歌手：87 首陶喆（从 My Anata 开始——那是听他的第一首）、45 方大同……
   「你的年度歌手：XXX，N 首。」——数据都是「你的」
② 情感高潮：你爱的 TA，变成了星星（方大同 2025-02-21 去世，45 首在歌单，含遗作《梦想家 The Dreamer》）
③ 曲风线：陶喆/方大同/丁世光/郭顶 = 华语 R&B 一条线（1-2 句点出）
④ 年份线：2016-2019 最凶（88/144/129/128）→ 2020 后放缓 → 2023 全年 22 → 最近补老歌
⑤ 几首单独记：每首 2-3 句（年份/专辑 + 一句核实过的热评或歌词原句），3 首左右
⑥ 听歌关键词收束：从数据提炼一个词（如「反复」）
结尾：年报式收束（「音乐还在，喜欢就还在。」），不分组不整理一句带过
落款：就到这里，下次见。—— Andiii碎碎念
```

⚠️ 已否写法（勿回退）：❌「像一本没写目录的日记」❌「喜欢过，就是喜欢过」❌ 满篇「你」轰炸 ❌ 数据罗列+空泛感慨 ❌ 开头解释默认名。
