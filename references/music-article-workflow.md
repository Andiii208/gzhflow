# 音乐/歌曲类公众号文章工作流（事实核查 + 专辑封面获取）

> 2026-08-04 陶喆 top3 推文实战沉淀。适用：用户点名某歌手/某几首歌写推文（"心中的top3"、"最爱的歌"、"深夜循环"类主题），要求出现专辑封面图。

## 0. 触发与风格路由

- 主题含「音乐/歌曲/歌手/听到一首歌」→ 写作层路由 **MorningRocks × WhatYouNeed 混合**（模式B：诗意+情感命名，第二人称）
- 配图路由：文艺/深度 → 手绘水彩 或 Zine 拼贴（见 image-style-routing.md，权威源在 GitHub 仓库，本地无副本）
- 用户要求「专辑图片」= 内文每首歌章节配**真实专辑封面原图**（网上找 or AI 重绘），封面头图可 AI 生成

## 1. 歌曲事实核查（动笔前必做，用户逐项核对）

每首歌必须核实 4 项，全部来自搜索确认，**不凭记忆写**：

| 核查项 | 方法 |
|---|---|
| 所属专辑 + 发行年份 | web_search「歌名 专辑 年份」 |
| 词曲作者 | 同上（如《天天》= 娃娃作词，写"陶喆作词"就错） |
| 歌词主题一句话 | 搜「歌名 歌词 主题/解读」，读百科/乐评确认核心意象 |
| **关键歌词原句** | 搜「歌名 歌词 + 你打算引用的那句词」，必须确认原句存在且一字不差 |

⚠️ 金句式写法高危：不要写「整首歌没有一句X」这类否定断言——实测想写《飞机场的10:30》"没有一句'我想你'"，实际歌词开头就有「我好想你」。**正确写法**：把断言改成对比「最打动人的不是那句'我好想你'，是那个细节——可乐剩一点给你」。

## 2. 专辑封面获取：iTunes Search API（最可靠，实测成功）

百度百科图片常被墙、浏览器可能启动失败——**iTunes API 稳定且给官方高清图**：

```bash
# 1) 搜歌手全部专辑，拿 artworkUrl100
curl -s "https://itunes.apple.com/search?term=%E9%99%B6%E5%96%86&entity=album&limit=50" | python -c "
import json,sys
d=json.load(sys.stdin)
for r in d['results']:
    print(r.get('collectionName',''), '|', r.get('releaseDate','')[:10], '|', r.get('artworkUrl100',''))
"
```

- 返回 URL 形如 `.../100x100bb.jpg`，**把 `100x100bb` 换成 `600x600bb` 或 `1200x1200bb`** 即得高清大图，直接 curl 下载
- 按 collectionName + releaseDate 双重匹配确认专辑（同名/多版本防混淆）
- iTunes 台区/美区封面可能与大陆版略异（如《黑色柳丁》是经典人眼+橙子封面，认准它）

## 3. 封面下载后必做 vision 验证

- 每张下载图 `vision_analyze` 确认画面内容与专辑对应（防下错图/URL 张冠李戴）
- ⚠️ vision 识别封面可能误判：实测《黑色柳丁》封面（灰度人眼特写+瞳孔橙球）被识别成 Radiohead《Kid A》——**换更高清版本（1200px）重新识别确认**，别急着换图源；也可能确实需要搜索「专辑名 封面 长什么样」交叉验证
- 专辑封面大多是方图（600×600），文章内文图若需 16:9 宽幅：居中裁切会砍掉上下内容（人脸/文字），可保留方形原图居中展示（`max-width:100%;margin:0 auto`），或 AI 二次重绘成宽幅艺术版

## 4. 结构模板（"top3/最爱"类实测可用）

```
标题：我现在心中的{歌手}top3（用户原话，20字内）
开头：场景切入（歌单/前奏/某个晚上），"现在听"与"以前听"的差异
正文：按排名逐首歌一节（倒序更吊胃口，或按用户给序）：
  - 歌曲名（粗体）→ 专辑+年份+作者（1-2句）
  - 歌词主题解读（引 1 句核实过的原词）
  - "为什么排第X"（个人理由，诚实第一）
  - 配该专辑封面原图
结尾：三首歌共同点收束（1段），不升华
落款：就到这里，下次见。—— Andiii碎碎念（gzh-design 签名区）
```

- 每首歌一节=每节一图，符合「配图宁多勿少」
- 引用歌词时注明出处语气（"陶喆唱"），不把歌词写成自己说的话
