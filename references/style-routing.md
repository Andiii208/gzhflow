# 文风路由方法论（Style Routing）

> 阶段② 写作层的方法论。原理：**按用户话题关键词自动匹配最适合的文风**，而不是每篇都用同一种写法。你的文风定义在 `config/styles.yaml`，完整风格指南在 `examples/styles/<name>.md`。

## 为什么要有风格路由

- 不同话题适合不同写法：「今天在食堂看到的事」适合白描/日常风；「焦虑与拖延」适合机制分析风；「黄昏与海」适合诗意留白风
- 单风格默认是错的——读者会腻，内容也会失真
- 路由给的是**推荐方向**，不是强制——用户手动指定风格时以用户为准

## 路由机制

```
用户话题关键词 → 匹配 config/styles.yaml 的 keywords → 命中风格
                → 未命中 → default_style
                → 用户手动指定 → 直接使用
```

## 如何定义一个风格（config/styles.yaml 条目）

```yaml
- name: "风格名"              # 唯一标识，default_style 也填这个名字
  description: "一句话描述"    # 让 Agent 快速理解这个风格
  keywords: ["关键词1", "关键词2"]   # 命中任一关键词则路由到此风格
  characteristics:            # 路由元数据（详细指南写 examples/styles/<name>.md）
    title: "标题公式"
    opening: "开头方式"
    persona: "我"             # 人称：我 / 你 / 我们
    paragraph: "段落节奏"
    tone: "语气调性"
    ending: "结尾方式"
```

## 风格差异的核心维度（定义风格时逐项思考）

| 维度 | 问题 |
|---|---|
| 标题 | 用什么公式？（为什么+现象 / 名词短语+留白 / 痛点疑问句） |
| 开头 | 怎么切入？（场景 / 提问 / 断言 / 比喻） |
| 人称 | 「我」高还是「你」高？还是「我们」为主？ |
| 段落 | 长短节奏？关键句是否独立成段？ |
| 金句 | 金句密度？收尾结构？（排比反转 / 断言 / 留白） |
| 配图 | 风格倾向？（无图 / 插画 / 摄影） |
| 结尾 | 升华还是平淡收束？ |

## 写作核心原则

**用目标风格的「表达方式」，说用户的「真实感受」→ 引发共鸣，不是抄袭。**

- 风格是精神（真诚、具体、平等的读者关系），不是公式
- 任何一篇被读者看出「在用公式写」的文章，都是失败的文章
- 参考源只留风格特征分析，不保存完整文章

## 自检三问（写作后）

1. 这句话是我真的想说的，还是为了「好看」写的？
2. 如果朋友读到，会觉得这是「我」写的吗？
3. 有没有一句话能让读者停下来想一会儿？
