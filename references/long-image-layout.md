# 公众号"高级排版"（纯图长图）复刻管线

2026-08-05 实测（案例：用户发来 mp.weixin.qq.com/s/FY-El4I8tlleBdkU-oq1-Q《二十岁决心当一棵树》问"能否画出来"）。

## 触发场景

用户发来一个"高级排版"公众号链接，问能否复刻/画出来/做成图片。
这类文章常常是**纯图排版**——正文不是 HTML 段落，而是被设计成一张/多张长图直接插入。

## 第一步：判定目标文章是不是纯图排版

1. `web_extract` 对 mp.weixin.qq.com 基本被拦（Blocked: private/internal network address）→ 用 **wechatDownload MCP**：
   `mcp__wechat_download_mcp__wechat(url, {"HTML": true, "MD": true})`，返回下载 URL（远端云存储）。
2. ⚠️ **MD 版往往只有图片链接、没有正文**；正文在 HTML 版的 `id="js_content"` 里。
3. 抓 HTML（curl 或 web_extract 都行，文件较大约 200KB）后，用 Python 提取：
   `re.search(r'id="js_content"[^>]*>(.*)', html, re.S)`（注意结束标签不一定是 `</div><script>`，直接抓剩余全部）。
4. 去掉 `<img>` 后若几乎无文字段落 → **纯图长图排版**。长图尺寸用 `file xxx.jpg` 确认（典型 1080×7000 JPEG）。

## 核心原则：AI 画图管"素材"、HTML 管"文字"

- 生图模型（Wan2.7-Image 等）画超长图 + 大量精确中文**必然翻车**（乱码、字数对不上）。
  **绝不让生图模型画正文文字。**
- 正确管线（四段式）：
  1. AI 生成**无文字**意象插画素材（prompt 末尾加"无任何文字"；树/月亮/鸭子/场景类）
  2. HTML/CSS 精确排版文字与装饰（文字 100% 可控）
  3. 无头浏览器按 1080px 宽截长图（msedge `--headless --screenshot --window-size=1080,高度 file:///...`，或 node+puppeteer-core 全页截图）
  4. PIL 切段成 ~7000px 长图插入微信

## 拼贴手账风（collage journal）风格速查

来自案例文章 vision_analyze 逐张分析结论：

- **背景**：米白纸面为主；分段用纹理盒子——浅蓝横格纸（正文叙述段）、牛皮纸（转折/提问段）、灰蓝渐变（场景段）
- **字体混搭**：超大粗黑体标题（核心字可单独换色，如"树"字亮绿色）、楷体副标题、宋体正文、手写体引文
- **配色**：低饱和蓝绿/米白/棕褐/灰黑为主，点缀少量高饱和亮绿/红/明黄破沉闷
- **装饰元素**：撕纸边缘、纸胶带、回形针、长尾夹、老式浏览器 UI（滚动条/音量图标）、复古人像剪贴画、杂志剪贴字母、噪点纹理
- **结构**：垂直叙事流 + 分段"视觉盒子"（每区独立背景/装饰），区块间充分留白；结尾常以完整场景插画收束（如雨夜路灯+小鸭子）

## 踩坑记录（本机 Windows + git-bash 实测）

- `web_extract` 拦 mp.weixin.qq.com → wechatDownload MCP 直接可用（本机已配好，无需桌面端）
- wechatDownload 的 **MD 无正文**，必须 HTML 版；js_content 正则要宽松
- **curl 中文文件名 `-o` 报 exit 23** → 用 URL 编码（`%E4%BA%8C...`）或 ASCII 文件名，重定向 `>` 也行
- **Windows 原生 Python 不认 MSYS `/d/` 路径** → 脚本和参数用 `D:/` 前缀
- 生图模型不能画精确中文正文——文字全靠 HTML 渲染
- 素材图与正文分离：素材即使有零星 AI 手滑文字也要重生成，不放行
- vision_analyze 是解析参考排版风格的主力工具（背景/字体/配色/装饰/结构一次问全）

## 文案注意（用户偏好）

- 试验/样图要**新内容**，不要复用旧文章（用户明确"我不要这个信息，我要新内容"）
- 文案先出全文给用户确认，满意再排版
- 用户否掉的第一版是"AI 文艺金句腔"（如"我在长根"）——走 andiii-writing-style 的碎碎念体：口语、零结构、不点题、金句≤1、禁对称排比
