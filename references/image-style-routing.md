# 配图风格路由表（wechat-content-automation 配图层）

> 2026-08-03 建。原则：**文风路由 → 配图风格 → 引擎**——写作层定了文风，配图跟着文风走，不默认全用水彩（v1.2 教训：单风格默认是错的）。

> ⚠️ **总原则（用户 2026-08-03 明确）：风格是参考，不是限制**——路由只给推荐方向，不强制；编译 prompt 时允许跨风格借用/混搭/偏离，以激发创意为准。质检门（质感/雷区底线）仍生效，风格本身是软的。

## 图源决策(2026-08-19 新增:真实图 vs AI 插画)

> 配图层第一步不是查风格,是先定图源。**每个意象块独立决策**,允许整篇混用真实图与 AI 插画——真实图管「见证」,AI 插画管「想象」,谁也替不了谁。

### 三问(逐意象块过)

1. **本体问:这个意象指向的东西,现实中存在且读者认得出吗?** 是(某软件/某张专辑/某地标/某产品)→ 真实图(网上找);否(回忆/情绪/比喻/抽象)→ AI 插画。
2. **功能问:这张图要「证明」还是「营造」?** 证明(截图/数据/界面/操作)→ 真实图;营造(氛围/情绪/风格统一)→ AI 插画。
3. **素材问:网上有没有现成的高质量合规真实图?** 有(官方图/CC0 图库/社区同人图/已验证渠道)→ 用真的;找不到或版权不明 → AI 兜底。

一句话原则:**意象本体在现实里→真实图(网上找);在内心→AI 图;找得到合规真实图永远优先。**

### 决策示意

```text
意象块清单
  ↓ 逐块三问(本体/功能/素材)
  真实图轨 → real-image-collection.md 渠道库(按类型取渠道) → 网上找图/下载/筛选/归因
  AI 轨    → 本路由表 → 引擎 → 四段式 prompt → 质检门 → 生成
  ↓ 混合组装(图序与意象对应,图下归因/说明)
```

### 与风格路由的关系

三问是「意象匹配 > 画风」的上游——**先定图源,再定画风**;图源确定后,AI 轨仍按下方路由表走文风→风格→引擎。真实图与 AI 插画混排时,图序节奏统一(正文 → 金句 → 图),真实图图说明带来源归因。

## 调用姿势(配图层)

```text
1. 文章文风已由写作层路由表确定(如 MorningRocks 风)
2. 🔴 **图源三问（2026-08-19 起必做）**：列出全文意象块清单，逐块过三问 → 分轨；真实图轨走 real-image-collection.md 渠道库（网上找图/下载/筛选/归因），AI 轨继续下一步。⚠️ 意象有真实照片更贴时，真实图优先于 AI 插画（2026-08-19 用户拍板）
3. 查本路由表 → 得配图风格 + 引擎(如 andiii-image-style)
4. skill_view(name='<引擎>') → **设计推理（design-reasoning.md 6 项，必做）** → 编译四段式 prompt → 质检门 → 生成 → 视觉复核 → 用户确认
4.5. **文章实体 → 统一色板**：全文若有一个反复出现的实体，定 3 个 hex 写进 manifest 的 `palette`（见下节）；没有就不加，别硬凑
5. 路由表状态为 ❌ 的风格：暂时回退手绘水彩或通用 prompt，并提示用户该风格待蒸馏
6. ⚠️ 针管笔（`07-pen-line.yaml`，原 `antibes-holiday`）质检门要带 `--engine pen-line`——它的材质词不是水彩系，不带会被「必需项缺失」误判 FAIL。它的 prompt 编译用其自带的 Comparative Validation（Physicality/Tempo/Instability/Shorthand/Relaxation/Transfer/Originality 七道主门）与 prompt-recipes.md，而非四段式
7. 🔴 针管笔试水教训（2026-08-06）：抽象线条碰撞（"两套天经地义撞在一起"）被用户否「感觉这图有点抽象了呀」；换**具体场景**（长桌两端背影+中央空杯，对应沉默/没说的话）通过。线条风配图同样要可识别的人/物/叙事意象（用 Story Scene / Functional Object 配方），不画脸、人物用背影/侧影轮廓。⚠️ 人物朝向关系必须画得出（2026-08-07 实测：prompt 写「两人面对面」但只画两个背影+左右分布，看起来像背对背被否——改为侧面剪影相对：一人面朝左一人面朝右、头互相朝向对方）。⚠️ 封面不可与正文图重复（用户纠正：「肯定不能跟正文图片是一样的呀」——正文图裁剪当封面会被要求换）。⚠️ Hermes image_generate(Wan2.7) 不收参考图 → 用文字化线条行为规格（漂移/错位/戛然而止/局部墨色加深/笔尖微不稳）代替 stroke-calibration.png。先 1 张具体场景试水再批量
```

## 文章实体 → 统一色板（2026-10-12 新增）

> 痛点：一篇文里出了 3 张 AI 图，各自都「符合引擎风格」，但摆在一起像三篇不同的文章——
> 因为油画颜料换了一批。**风格一致 ≠ 色板一致。** 同一篇文的图必须共享一套色。

### 什么叫「文章实体」

不是每篇都有。指的是**全文反复出现、且自带色彩的那个东西**：

| 类型 | 例子 | 色板从哪来 |
|---|---|---|
| 物件 | 某款相机、某张黑胶、某个杯子 | 实物本身的色彩 |
| 界面 | 某个 App 的主色、某个游戏的界面 | UI 主色 + 强调色 |
| 场景 | 某个季节的操场、某座城市的黄昏 | 场景实拍的主色 |
| 品牌 | 某家咖啡店、某个杂志 | 品牌色（取低饱和版） |

找不到这样一个实体 → **不强凑**，整篇用引擎自带的纸底 + 晕染，不加统一色板。
硬编一套色板反而会把不同的图框死。

### 三步

1. **定实体**：从素材/正文里挑出那个反复出现的实体（一个就够，别贪）
2. **取色**：定 3 个 hex —— 1 个主色（实体最标志的颜色）+ 1 个辅色 + 1 个中性色。
   拿不准就从真实图里吸色（截图后用取色工具），**别凭记忆写「深蓝」**
3. **写进 manifest**：顶层加 `palette` 字段

```json
{
  "article": "标题",
  "palette": ["#3A4A5A", "#C4A484", "#7A6A58"],
  "images": [ ... ]
}
```

`image_batch.py` 会把色板接到每张图的 prompt 末尾：
`统一色板：#3A4A5A #C4A484 #7A6A58（仅作晕染辅色，不覆盖纸底与纸感）`。
个别图想脱离色板 → 该图单独写 `palette` 覆盖（如黑白插图）。

### 三条纪律

- **只染不覆**：色板是**晕染辅色**，不覆盖引擎的纸底与纸感词。水彩引擎还是水彩，只是颜料换了
- **3 个正好**：主色 + 辅色 + 中性。给了 6 个色，模型反而画成花猫
- **宁可少给**：拿不准就只给 1 个主色。色板的作用是「看起来是一家人的」，不是「精确还原实物」

### 一致性怎么验

出图后并排看：**3 张图的晕染主色调是不是同一族？** 是 → 过；
每张都漂在别的色系 → 说明色板没生效（检查是否被某张图的 `palette` 覆盖，或 prompt 里的色词跟色板打架）。
先出 1 张试水，确认色板效果，再批量。
