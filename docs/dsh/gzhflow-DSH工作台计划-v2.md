## 0. 结论先行

**当前状态一句话**：功能上 P0/P1 已交付、P2 做了一半；设计上是「能看，但没有设计感」；可视化是「有图形，没有信息」。

三件必须马上解决的真问题：

| # | 问题 | 证据 | 状态 |
|---|---|---|---|
| 1 | **远端仓库缺 JSON 契约**：工作台依赖的 4 个脚本 `--json` 只在本地未提交工作区，GitHub 上没有。换机器即断。 | `git show HEAD:scripts/ai_flavor_score.py \| grep -c json` = 0（审计 §0.1） | ✅ 已修：提交 `3abff63` 并推送到 `origin/main` |
| 2 | **前端没有设计系统**：自建了一套 CSS 变量，但没接 DSH 的字体阶/圆角/阴影/动效令牌；四张 KPI 卡同款同构、Hero 大片留白、卡片全是一个形状。 | 实拍截图：Hero 标题下 120px 空白、四个圆角卡片无差异、空态画了一个 0 的环 | ⏳ 本计划 S1–S4 |
| 3 | **可视化没有信息量**：空数据画空图（0 值环、平线 sparkline）、柱状图无刻度无量纲、轨迹「构成」环形图永远只有一个色块。 | 实拍截图：轨迹页 3 张卡全是 0 | ⏳ 本计划 S4 |

**本计划的目标**：把工作台从「一个把文件读出来显示的插件」做成「一个能一眼看清这一篇写到哪、写得怎么样、Agent 干了什么的编辑部控制台」，同时把 v1 遗留的功能缺口全部收口。

## 2. 设计语言 v2

### 2.1 定位：编辑部控制台，不是 dashboard 拼盘

工作台的用户是「一个正在写一篇公众号文章、同时盯着 Agent 干活的作者」。他要的不是 KPI 墙，而是三个问题的答案：

1. **现在到哪一步了，卡在哪儿？**
2. **这一版写得怎么样，哪里要改？**
3. **Agent 刚才干了什么，靠不靠谱？**

所以每一屏只有一个主角，其余是配角。v1 的问题是四张同款 KPI 卡平权竞争，谁都不突出。

### 2.2 三条原则（继承 v1 §3.3，并收紧）

- **信息优先**：没有信息量的图形一律不做（killed: 0 值环、平线 sparkline、纯装饰图标块）。宁可空态给一句可执行的下一步。
- **一切可溯源**：屏幕上每个状态都能指回一个文件或一条会话事件；指不回去就显示「未知」，不猜（v1 §3.3 §8）。
- **减法**：任何新增控件必须通过「它是否减少了一次复制 / 查找 / 回忆」的检验（v1 §3.3）。本页不再新增第 5 个导航项，导航固定 6 项。

### 2.3 视觉语言

- **色彩**：以 DSH 主题为底（`--dsw-alias-*`），工作台自有语义色只保留 5 个角色——青瓷绿（主/进行中）、琥珀（提示/待办）、玫红（失败/阻断）、靛蓝（工具/外部）、紫（决策/产物）。每个角色一套 `solid / soft / line` 三态。明暗各一套，不共用色值（v1 的暗色只是把色值换了一遍，没有语义层的重新分配）。
- **字体**：正文用 DSH 的 `--dsw-font-*` 阶（16/14/13/12/11），长文阅读区单独放大到 15.5px/1.95。数字全部 `tabular-nums`。标题层级最多 3 级。
- **间距**：4px 基准刻度 4/8/12/16/24/32/48。卡片内边距 16/20，卡片间距 16（v1 用 14/16/18/20/24/26 混用，没有刻度）。
- **圆角**：4/8/12/16 四档；`--dsw-radius-*` 已有 xs/sm/md/lg/xl/panel 直接复用。v1 的 34px 手机圆角是特例，保留。
- **阴影**：改用 DSH `--dsw-elevation-soft / panel / prominent`（1px 描边 + 低透明投影），去掉 v1 手写的三层渐变阴影。
- **动效`：`--ds-transition-duration-fast(0.1s) / normal(0.2s) / slow(0.3s)` + `--ds-ease-in-out`。只允许三类动效：入场淡入上移、状态切换、悬停反馈。`prefers-reduced-motion` 全关。

## 3. 设计系统 v2

### 3.1 令牌

**直接用 DSH 的（不重造）**：

```
背景    --dsw-alias-bg-base / bg-layer-1 / bg-layer-2 / bg-layer-3 / bg-skeleton
描边    --dsw-alias-border-l1 / l2 / l3 / l4
文字    --dsw-alias-label-primary / secondary / tertiary / dimmed / caption
交互    --dsw-alias-interactive-bg-hover / active / hover-accent / hover-danger
按钮    --dsw-alias-button-primary-fill / ghost-active-fill / info-fill / floating-fill
字体    --dsw-font-xl-24 / l-20 / m-18 / base-16 / s-14 / xs-13 / xxs-12 / xxxs-11
圆角    --dsw-radius-xs(4) / sm(8) / md(12) / lg(16) / xl(20)
阴影    --dsw-shadow-lv1 / lv2 / lv3，--dsw-elevation-soft / panel / prominent
动效    --ds-transition-duration-fast|normal|slow，--ds-ease-in-out
等宽    --ds-font-family-code
```

**工作台自有（角色化，明暗两套）**：

```
--gzw-accent{,-strong,-soft,-line}   青瓷绿：主色、当前阶段、进度
--gzw-warn{,-soft,-line}             琥珀：待办、待审、提醒
--gzw-danger{,-soft,-line}           玫红：FAIL、失败、阻断
--gzw-info{,-soft,-line}             靛蓝：工具调用、外部产物
--gzw-decision{,-soft,-line}         紫：决策记录、复盘
--gzw-surface{,-2,-raised}           三层表面
--gzw-line{,-soft,-strong}           三级描边
--gzw-ink{,-2,-3}                    三级文字
```

### 3.2 组件清单

基础组件（重写）：`Card / SectionHeader / Btn / Chip / Tabs / Stat / MetricRow / KeyValue / Empty / ErrorBlock / Skeleton / Toast / Divider / Toolbar / Field`。
数据组件（重写）：`StageFlow`（SVG 阶梯）、`ScoreGauge`（分级环形）、`RuleBars`（带刻度规则分布）、`SentenceHistogram`（句长直方）、`RhythmStrip`（带 200 字阈值线的段落条）、`Timeline`（轨迹时间轴）、`ActivityDonut`（构成，仅有数据时渲染）、`ToolRank`（工具调用 Top N）、`ArtifactTimeline`（产物时间线）、`BudgetMeter`（预算条）、`CheckList`（发布清单）、`DiffView`（手改 diff）。
交互：`InlineConfirm`（两次点击，不用弹窗）、`FilterChips`、`SearchField`、`KeyboardHelp`、`EmptyState`。

### 3.3 明暗双套与无障碍

- 深色：`body[data-ds-dark-theme]` 下重新分配角色色值（不是简单反色），正文对比度 ≥ 4.5:1，次要文字 ≥ 3:1。
- 焦点环：所有可交互元素 `:focus-visible` 用 accent 2px 环。
- 颜色不是唯一信号：FAIL/WARN 同时带文字与图标。
- 图表附 `title`/`aria-label`，正文与图表同源同数据。

## 4. 信息架构 v2

导航固定 6 项：**总览 / 阶段 / 轨迹 / 产物 / 库 / 绑定**（新增「库」= 四库 + 复盘；「新写一篇」作为总览页与库页里的动作按钮，不占导航位）。

页面骨架：

```
顶栏（sticky）
├ 品牌 + 当前篇一行摘要（标题截断 + 阶段 + 进度环 + 绑定状态）
├ 主导航（6 项，右侧动作：刷新 / 环境自检 / 诊断）
└ 内容区（max-width 1440，12 列栅格）
```

| 页 | 主角 | 配角 |
|---|---|---|
| 总览 | **当前篇状态**（大标题 + 阶段进度 + 下一步动作） | 阶段流水线、四个关键指标（各带真实图形）、审阅条 |
| 阶段 | **当前阶段的工作区**（阶段身份 + 本阶段产物 + 本阶段动作） | 阶段内导航、统计 |
| 轨迹 | **Agent 干了什么**（时间轴为主） | 构成、工具 Top N、失败与决策 |
| 产物 | **产物清单**（按阶段分组 + 大小条） | 产物时间线、预览 |
| 库 | **四库 + 复盘**（inbox/voice/lessons/voice-samples 只读） | 记一笔入口、手改记录 |
| 绑定 | **会话绑定**（当前绑定 + 候选列表 + 写操作就绪状态） | 绑定说明 |

> **这一轮修掉的真实缺陷**（不是设计问题，是功能坏了）：

> 1. `workspaceFiles.read` 的 `limit` 上限是 5000，客户端传 20000 → **所有工作区读取都在失败**，一直静默回退到宿主命令。四库因此读不到。改成 5000 行分块读。
> 2. 体检明细的行号是**整份文件**的行号（含 frontmatter），而正文渲染用的是剥掉 frontmatter 后的行号 → 点「L17」定位不到。改成带偏移量渲染，现在点哪条都能跳到对应段落并高亮。

> 5. 空状态里的「0 值环 / 平线 sparkline」是装饰性图表，已全部删除：无数据时给文字和下一步动作。
